# AI 自動面試系統

依《AI 自動面試系統流程規劃》第一階段範圍實作的招募初步訪談平台。
所有 AI 推論都在本地執行，資料不出內網。

## 環境需求

- Node.js 18 以上
- [Ollama](https://ollama.com)（本地 LLM，取代公有雲 API）

## 安裝與啟動

```bash
# 1. 安裝套件
npm install

# 2. 建立環境設定
copy .env.example .env        # Windows
# cp .env.example .env        # macOS / Linux

# 3. 建立資料庫
npm run db:push

# 4. 安裝並啟動本地模型（另開一個終端機）
ollama pull qwen2.5:7b-instruct
ollama serve

# 5. 啟動系統
npm run dev
```

開啟 http://localhost:3000

系統健康檢查：http://localhost:3000/api/health
（會回報資料庫、本地模型、SMTP 三項是否就緒）

## 使用流程

1. **建立職缺** — 首頁 → 建立新職缺。「AI 面試重點」每行一項，會直接影響面試題目。
2. **加入候選人** — 進入職缺頁，填寫姓名 Email 並上傳履歷（PDF / DOCX / TXT）。
   系統會用本地模型解析成結構化欄位。
3. **確認解析結果** — 進入候選人頁，檢查解析是否正確，可重新解析或標記為已確認。
4. **發送邀請** — 點「生成大綱並發送面試邀請」。系統會產生該候選人專屬的面試大綱並寄出邀請信。
   未設定 SMTP 時，信件內容會印在終端機，連結可直接複製使用。
5. **候選人面試** — 候選人開啟連結 → 選擇立即開始或預約 → 同意告知 → 進行訪談。
6. **審核報告** — 面試結束後系統自動產生報告。到「待審核」頁面檢視，
   對照逐字稿確認無誤後標記 Proceed / Hold / Need Follow-up / Not Suitable。

## 設計上的幾個決定

**報告要求附原句**
LLM 摘要有幻覺風險。報告的每個亮點、疑慮、成果都要求模型附上逐字稿原句
（`evidence`），Recruiter 可以直接比對，找不到原句的項目模型不應輸出。

**追問次數有上限**
`interview-engine.ts` 為每個階段設了問答預算，同一件事最多追問兩次，
仍無法確認就記入「未確認資訊」往下走。這是為了控制 15-20 分鐘的總長度，
也避免小模型陷入重複提問。

**AI 不做判斷**
系統不產生分數、不排名、不建議錄取。篩選依據是每位候選人自己的面試內容，
最終判斷由 Recruiter 完成（文件第十二章）。

**個資保護**
候選人履歷存在 `uploads/`，已排除於版控之外。候選人可選擇不保留錄音。
所有 LLM 呼叫都打向 `OLLAMA_URL`，預設為本機，不會外連。

## 正式環境調整

**資料庫改用 PostgreSQL**

1. `prisma/schema.prisma` 的 `provider` 改為 `"postgresql"`
2. `.env` 的 `DATABASE_URL` 改為連線字串
3. 執行 `npm run db:push`

**模型改用 GPU 伺服器**

`.env` 的 `OLLAMA_URL` 指向內網 GPU 伺服器即可。
若改用 vLLM 等非 Ollama 服務，只需改寫 `src/lib/llm.ts` 的 `chat()`，
其餘程式不受影響。

**Email**

在 `.env` 填入公司內部 SMTP 設定。未設定時系統會將信件內容輸出到終端機。
